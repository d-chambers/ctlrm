# Managed sessions

A managed standalone session occupies one existing Git worktree and branch. It does not need a workflow graph or task object. Launch with `ctlrm --root /path/to/worktree session start --provider claude`. Use `session status` to inspect the committed request result, session ID, generation, native recovery record, and any diagnostic. Status never launches agents.

Use `session prompt --session-id ID --generation N --file prompt.md` to deliver text through the durable mailbox. The provider must acknowledge the work ID before acting. Another prompt is accepted after the previous prompt completes. Keep the returned request ID and pass `--request-id ID` when retrying an uncertain submission. Reusing an ID with different content is an error. Terminal input contains only a bounded mailbox reference; multiline prompt contents stay on disk.

`session attach --session-id ID` opens the native tmux client with inherited terminal I/O after libtmux verifies its target (libtmux 0.62’s attach helper captures I/O and cannot attach interactively). Session creation, inspection, and ownership remain in the libtmux adapter. This exposes native terminal interaction and any provider trust or tool-approval prompts. Directly entered prompts are outside ctlrm's durable dispatch guarantee. A readiness timeout blocks visibly; inspect the terminal rather than assuming the provider completed work. Human approval of a provider tool call is distinct from workflow approval.

`session stop --session-id ID` explicitly stops the owned terminal process group and disables automatic recovery. `session resume --session-id ID` resumes the acknowledged native conversation after the old provider has exited. `session replace --session-id ID` explicitly starts a fresh conversation with the same participant role and a new generation. Replacement is never reported as native recovery. Unfinished work requires a status reconciliation before continuation, including after replacement. Unknown or stale-generation reports remain visible as rejected request evidence.

`supervisor stop` stops supervision while preserving agent terminals. `supervisor start` replays accepted state; `supervisor start --foreground` is useful for debugging or a service manager. Logs are under `.ctlrm/supervisor/logs/`. The supervisor uses a persistent flock inode. Status reads the kernel lock table and verifies the advisory owner metadata against that held inode; it does not acquire the lock merely to probe liveness or trust a stale PID file. Closing the CLI or TUI does not stop the supervisor. After host reboot, start the supervisor again; login-service installation is deferred.

The root, expected branch, roster, profiles, and coordination ID are immutable. Changing branch pauses dispatch and outcome acceptance. Restore the recorded identity and run `supervisor reconcile` to unpause. Separate linked worktrees receive independent runtime directories and tmux socket namespaces. The local Git-resolved exclude file gains an idempotent `/.ctlrm/` entry if needed. Starting a second unrelated instance in the same worktree is rejected. Existing legacy room data requires a fresh worktree or explicit `--adopt` with an exactly compatible coordinator, roster, and prompt.

Provider profiles are YAML objects supplied with `session start --profile FILE`. Built-in providers are `claude` and `codex`; custom command profiles require explicit launch/resume argument templates. Fields include `executable`, `arguments`, `context`, `required_environment` (names only), `registration_timeout`, `recovery_limit`, and `backoff`. The recovery limit counts consecutive unsuccessful resume attempts and resets after accepted readiness. Native identity/persistence flags remain adapter-owned. The effective provider context directory must match the snapshot on resume. Credential values are never written to the profile or recovery record. Provider permissions and trust remain governed by the configured provider; ctlrm does not turn them off. Claude profiles default to `input_mode: manual`, keeping prompts in the mailbox for manual terminal delivery. To opt into automatic Claude delivery, select `input_mode: unattended` with `--permission-mode dontAsk`, which denies tools not already allowed by your provider configuration. Custom command profiles must explicitly declare that their input has no approval dialogs before using unattended mode. This prevents terminal wake-up Enter keys from selecting an approval dialog. Codex uses the `native` transport described below, which does not type into provider dialogs.

The runtime currently requires Linux process identity information from `/proc`, local POSIX storage supporting hard links and directory fsync, tmux 3.2a or newer, and libtmux 0.62.x. Real adapter tests use isolated tmux servers. Native Claude recovery was measured separately in [provider recovery evidence](provider-session-recovery.md); fake provider tests do not prove another provider's native resume support. The [mixed-provider evidence](evidence/mixed-workflow-2026-09-05.json) additionally covers automatic routing and native recovery within a review loop.

Events form a hash-chained sequence with an initial snapshot and immutable state deltas. Earlier full-snapshot events remain replayable. Internal sequence gaps and checksum corruption stop the supervisor. Never edit or remove accepted events: a hash chain alone cannot detect deliberate removal of a valid suffix or the whole journal. Malformed client requests are diagnosed without hiding valid submissions. The journal guarantees one accepted request/transition and one logical mailbox assignment; it does not promise exactly-once external agent effects. Repeated wake hints require acknowledgment of the existing work ID. Uncertain effects remain blocked for reconciliation.

## Measured managed recovery

On 2026-09-05, the managed service launched Claude Code 2.1.261 in a disposable linked worktree using libtmux 0.62.0 and tmux 3.4. The narrowly scoped test profile used `dontAsk`, the Read tool, and only the control-room CLI Bash prefix in that worktree. The agent accepted its role, published native recovery instructions, acknowledged a mailbox prompt, remembered a test token, and reported completion. The test killed the verified provider child with SIGKILL while leaving its host intact. The supervisor automatically resumed the same native ID in generation 2, and the agent acknowledged the new generation.

A new mailbox prompt asked for the earlier token without repeating it or permitting old-file reads. Claude read that new assignment, acknowledged it, recalled the exact token from native conversation history, and reported completion. The session was then explicitly stopped. The structured [managed recovery evidence](evidence/managed-native-recovery-2026-09-05.json) records the IDs, work payloads, recovery vectors, and stop result. This proves completed-conversation context retention; deterministic recovery tests separately cover acknowledged unfinished work and uncertain dispositions. It does not claim exactly-once tool side effects or arbitrary tool-state recovery.

A second live test interrupted acknowledged work, resumed the same Claude conversation, and completed the same work ID in the new generation. The reviewed host also published its durable exit observation. See [interrupted-work evidence](evidence/managed-interrupted-recovery-2026-09-05.json).

Codex native transport was measured with codex-cli 0.153.4: the runner resumed the same native thread after process death, recalled retained context, completed the same work ID, and stopped explicitly. See [managed Codex evidence](evidence/managed-codex-recovery-2026-09-05.json) and the [official non-interactive API](https://developers.openai.com/codex/noninteractive). The runner stays owned by the terminal host, while individual turns may finish normally. Its attached terminal displays streamed output; submit work with the CLI instead of typing into that runner. Managed Codex profiles require `input_mode: native`; interactive TUI profiles are rejected because current Codex versions may run work on a shared daemon outside the terminal host.
