# Reusable workflows

`ctlrm workflow validate --template workflow.yaml` validates a version 1 template. Templates define named profiles, roles, an entry step, explicit outcome transitions, and a bounded number of executions. `profiles` maps names to the provider profiles described in [managed sessions](managed-sessions.md). Human roles have no profile. A terminal destination is `terminal:completed`, `terminal:rejected`, or `terminal:failed`.

Submit with `ctlrm --root WORKTREE workflow submit --template workflow.yaml --title "Task" --file task.md --request-id SUBMISSION_ID`. Every role defaults to a participant with the same name; repeated `--bind ROLE=PARTICIPANT` options may supply a complete alternative binding. Reusing a submission ID with identical inputs retries initialization. A different task requires another worktree. The template, profiles, task, and bindings are immutable snapshots; later changes to the source template cannot change the run.

`workflow status` exposes run progress, execution history, session state, and diagnostics. Each assignment records an execution ID and exact acknowledgment/report commands. Agents and humans must acknowledge before acting and report an explicitly allowed outcome. Humans first accept their assigned role with `workflow join --participant NAME`. `workflow report` is also the human-response command. A rejected stale or unknown outcome remains visible in request history and cannot advance the task.

Each review-loop visit has a new execution ID and carries the previous summary. Accepted transitions and assigned mailbox IDs survive supervisor restart; publication and terminal hints may repeat, while the logical assignment does not. Human approval is independent of provider tool permissions. The supervisor validates all profiles before submission, launches the active agent role lazily, and reuses healthy sessions across visits. Explicitly stopped sessions stay stopped until resumed or replaced.

The coordination area is cooperative, writable by the same operating-system user. Role signatures validate workflow identity and intent; they do not authenticate a human against another process with the same filesystem access. Managed agent environments are prevented from calling human response operations as an accidental role crossing, but a malicious same-user process can remove that environment marker or alter files. Use a separately authenticated service for security-sensitive approvals; that is outside this local runtime.

The event journal retains its initial snapshot and records subsequent state deltas, keeping old execution history and request results out of new record sizes. Replay supports the earlier full-snapshot event format. Immutable records remain bounded to 8 MiB each.

Each outcome captures an immutable artifact manifest under `.ctlrm/artifacts/`, recording HEAD, dirty status, a Git index digest, and content hashes for tracked and non-ignored untracked files. Runtime files are excluded. Symlinks record link text without reading their targets. Clean nested Git repositories/submodules record their commit; dirty nested repositories require committing their changes before handoff. Capture is bounded to 10,000 files and 64 MiB. Assignments name the input artifact, which acknowledgment and report commands must repeat with `--input-artifact`. Each new template step must explicitly set `verify_input`: use `true` for review/approval steps and `false` for implementation steps that intentionally change the input. A step with `verify_input: true` checks every outcome against that version, regardless of its name; changed content leaves the execution active with a rejected request. These checks detect changes at observation time and cannot prevent concurrent manual writes after inspection.

`workflow cancel` commits cancellation before stopping every owned agent, including while branch drift has paused dispatch. `workflow retry --execution-id ID --reason TEXT` explicitly abandons a visit and creates a new one within the template's execution limit. Stop its agent first, retry, then use `session resume` or `session replace`. Retry refreshes any input artifact against the current worktree, making a new review acknowledgment necessary. Native recovery retains the execution ID but requires reconciliation and current-generation acknowledgment before an outcome. A generic session completion cannot bypass workflow outcome validation.

Codex defaults to a terminal-owned `codex exec --json` turn runner, using `exec resume` for further native turns. Generation-specific immutable input hints wake it without typing into a provider permission dialog. This uses Codex's configured permissions and credentials. Claude interactive automation still requires an explicit unattended profile; its default profile is manual. Managed agent reports do not silently restart an explicitly stopped supervisor; restart it with `supervisor start` to accept pending requests.

A runnable [implement/review/approval template](../examples/implement-review.yaml) uses two independent Codex sessions with one shared profile definition. Output intended for handoff must be tracked or non-ignored; add intentionally ignored output to Git before reporting it so its version is included. The [mixed-provider acceptance record](evidence/mixed-workflow-2026-09-05.json) demonstrates Codex implementation, Claude review, native interruption/recovery, requested changes, supervisor restart at a pending handoff, the human response API, and isolated reuse of an unchanged template.

Earlier immutable template snapshots without `verify_input` remain replayable using their original `approved`-outcome policy. New submissions must declare the policy for every step, making an outcome rename independent of version enforcement. Retry inputs explicitly identify the abandoned execution that was recaptured and retain the previous artifact reference; they do not attribute edited content to the original producer.

Native bootstrap turns that finish without accepted readiness are redelivered at a bounded interval while startup is still allowed. The registration timeout remains the upper bound; visible blocked startup requires explicit intervention. A failed native turn exits the runner and enters generation recovery rather than blindly repeating a turn that may already have performed effects.

For a step whose outcomes have different verification requirements, set `verify_input: false` and list the checked transition names in `verified_outcomes`. Those names must exist in the step's transitions. Old snapshots preserve their original approval-only policy through this representation; they are not silently changed into all-outcome verification.

Artifact manifests created before staged-index hashing need a refreshed review artifact before a later version-checked approval; an older manifest cannot establish that the staging area stayed unchanged. Runtime startup and completed run inspection remain compatible with those records.
